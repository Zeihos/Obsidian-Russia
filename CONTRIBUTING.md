# Участие в разработке OBSIDIAN RUSSIA

Спасибо за интерес к проекту! Здесь можно сообщать об ошибках, предлагать улучшения и обсуждать доработки сайта, форума и Wiki.

[← На главную](README.md) · [План развития](docs/ROADMAP.md) · [Безопасность](SECURITY.md)

## Как сообщить об ошибке

Перед отправкой проверьте, нет ли уже похожего [Issue](https://github.com/Zeihos/Obsidian-Russia/issues). Используйте шаблон **«Сообщить об ошибке»** и укажите:

1. Где возникла проблема: сайт, форум, Wiki или общий запуск.
2. Какие действия приводят к ошибке.
3. Что ожидалось и что произошло на самом деле.
4. ОС, версию Python, браузер и текст ошибки (если они важны).
5. Скриншот без персональных данных — при необходимости.

**Никогда не публикуйте** пароли, токены, cookies, действующие SQLite-базы, платёжные данные и персональную информацию.

## Как предложить улучшение

Откройте Issue с шаблоном **«Предложить улучшение»**. Опишите, зачем оно нужно игрокам или команде, и что должно измениться. Не обязательно сразу писать код.

## Как предложить изменение кода

1. Обсудите крупное изменение в Issue, чтобы избежать дублирования работы.
2. Создайте отдельную ветку от актуальной `main`.
3. Меняйте только необходимые файлы; сохраняйте совместимость с локальным запуском.
4. Для новой логики по возможности добавьте тест.
5. Откройте Pull Request на русском языке, используя шаблон.

Примеры веток: `fix/forum-search`, `feat/wiki-catalog`, `docs/getting-started`.

### Проверка перед Pull Request

Нужен Python 3.12+:

```bash
python -m compileall -q "Сайт" "Форум" "Вики" dev.py tests
python -m unittest discover -s tests -p "test_*.py" -v
```

В CI проверки запускаются на Windows и Linux. Тесты используют временные базы, а локальные данные должны оставаться вне Git.

## Оформление и стиль

- Текст интерфейсов и пользовательскую документацию пишем **на русском**.
- Название бренда — **OBSIDIAN RUSSIA**.
- Сохраняем основной красно-чёрный визуальный стиль.
- Не подменяем настоящие игровые данные вымышленными ценами, онлайном или IP-адресами.
- Не удаляем фирменные материалы без обновления зависимых путей в `static/`.

## Безопасность и сторонний код

Уязвимости сообщайте приватно по инструкции в [SECURITY.md](SECURITY.md), а не публичным Issue с рабочим эксплойтом. Не добавляйте «сливы» чужого кода, графики или базы пользователей без подтверждённых прав.

**Важно:** публичный GitHub-репозиторий не равен проекту с открытой лицензией. Отдельная лицензия для OBSIDIAN RUSSIA пока не указана; права на повторное использование и распространение нужно согласовывать с владельцем.
