# Восстановление пароля OBSIDIAN RUSSIA

[← Главная](../README.md) · [Развёртывание](DEPLOYMENT.md) · [Безопасность](../SECURITY.md)

## Что реализовано

Сайт поддерживает **восстановление пароля по одноразовой ссылке в email**. Форма доступна по пути `/forgot`, страница установки нового пароля — `/reset?token=...`.

- Ссылки действуют **30 минут** и погашаются после первого успешного применения.
- В SQLite сохраняется **только SHA-256 хеш** токена и дата истечения срока. Сам токен виден только получателю письма.
- После сброса закрываются **все сеансы сайта**, аннулируются неиспользованные SSO-коды и увеличивается `auth_version` — ранее связанные форумные SSO-сеансы отклоняются при следующем обращении к форуму.
- Ответ формы одинаков для зарегистрированных и незарегистрированных email. Есть ограничения запросов по адресу и IP.
- При сбое SMTP выданный токен отменяется; система **не выдаёт письмо за успешно доставленное**.
- На странице сброса используется `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, а секрет из URL скрыт в HTTP-логах.

**Отправка писем отключена, пока владелец не задаст корректные переменные SMTP.** Никаких фиктивных писем, публичных ссылок для обхода почты и секретов в GitHub.

## Настройка SMTP

Настройте переменные окружения процесса **основного сайта** (не форума и не Wiki):

| Переменная | Значение |
| --- | --- |
| `OBSIDIAN_BASE_URL` | `https://site.example.org` — внешний HTTPS-адрес сайта |
| `OBSIDIAN_SECURE_COOKIES` | `1` в публичном окружении |
| `OBSIDIAN_SMTP_HOST` | SMTP-сервер вашего почтового провайдера |
| `OBSIDIAN_SMTP_PORT` | Обычно `465` для SSL или `587` для STARTTLS |
| `OBSIDIAN_SMTP_SECURITY` | `ssl` или `starttls` — незащищённая отправка не поддерживается |
| `OBSIDIAN_SMTP_FROM` | Подтверждённый адрес отправителя, например `no-reply@example.org` |
| `OBSIDIAN_SMTP_USER` | Логин SMTP, если используется авторизация |
| `OBSIDIAN_SMTP_PASSWORD` | Пароль приложения или SMTP-секрет, если используется авторизация |

`OBSIDIAN_SMTP_USER` и `OBSIDIAN_SMTP_PASSWORD` должны быть заданы вместе либо оба оставлены пустыми, если сервер настроен на разрешённую отправку без SMTP AUTH через TLS.

**Не записывайте реальные SMTP-данные в `.env.example`, README, тикеты, журналы или GitHub Actions.** Для продакшена используйте менеджер секретов. Убедитесь, что домен отправителя настроен по требованиям провайдера, включая SPF/DKIM/DMARC при необходимости.

Адрес восстановления формируется только из `OBSIDIAN_BASE_URL`. Публичное восстановление разрешено только для HTTPS-адресов; HTTP допускается только для `localhost`/`127.0.0.1`/`::1` в локальной разработке.

После настройки запустите сайт и проверьте настоящую доставку письма на контролируемый адрес. Наличие успешных тестов GitHub Actions **не означает**, что отправка вашим SMTP-провайдером уже настроена или проверена.

## Перед публичным запуском

Существующие email в базе могли регистрироваться **без подтверждения владения почтовым ящиком**. Поэтому перед массовым включением восстановления следует провести аудит существующих адресов и внедрить подтверждение email, чтобы избежать споров о владении учётными записями. Не запускайте восстановление для реальных пользователей, если нет согласованной процедуры обработки таких конфликтов.

Также необходимы антибот-защита, лимиты запросов на уровне прокси, мониторинг ошибок отправки без логирования токенов, HTTPS и правила обработки пользовательских данных. Текущие in-memory лимиты действуют в рамках процесса и не заменяют распределённую защиту.

## Локальные проверки

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

В `tests/test_password_recovery.py` HTTP-сценарий проверяется с **подменённой отправкой письма только в тестовом процессе**. Тесты покрывают формирование ссылки, хеширование, срок действия, защиту CSRF, невозможность повторного использования, отказ SMTP и отзыв сеансов. Отдельный тест проверяет формирование сообщения через SMTP SSL с имитированным TLS-транспортом. Реальная доставка внешнему адресату в CI не выполняется.
