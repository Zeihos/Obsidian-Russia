# Управление сеансами OBSIDIAN RUSSIA

Сайт, форум и Wiki позволяют завершать активные входы с других устройств и выходить из текущего аккаунта **на всех устройствах**. Все действия выполняются сервером, по POST с CSRF-защитой, и сразу удаляют соответствующие записи из SQLite.

## Где найти

| Компонент | Раздел | Возможности |
| --- | --- | --- |
| Сайт | `/account` → «Безопасность сеансов» | Количество активных входов, закрытие остальных, выход со всех устройств |
| Форум | `/account` → «Активные сеансы» | Количество активных входов, закрытие остальных, выход со всех устройств |
| Wiki | Редакторская панель `/admin` | Закрытие остальных входов редактора, выход со всех устройств |

## Как это работает

**Завершить другие сеансы:** сохраняет текущий вход пользователя в **этом** приложении, удаляет остальные активные сессии того же аккаунта. Другие пользователи не затрагиваются.

**Выйти на всех устройствах:** удаляет все сессии текущего аккаунта, включая текущую, и удаляет cookie авторизации в браузере. Для продолжения работы нужно войти заново.

Форум записывает операции в журнал действий модерации, Wiki — в журнал аудита редакторов.

### Важно об SSO

Сайт и форум имеют **разные базы сессий**. Для аккаунта, связанного с SSO, смена пароля либо «Выйти на всех устройствах» **на сайте** отзывает связанные форумные сеансы при следующем запросе к форуму. Если сайт недоступен, проверка SSO не проходит и доступ временно не предоставляется; локальные форумные аккаунты работают независимо.

Полного глобального выхода нет: выход из одного сеанса сайта, «Завершить другие сеансы» и выход из форума не закрывают все входы в остальных приложениях. Wiki полностью независима. Подробнее — [SSO](SSO.md).

При обнаружении компрометации аккаунта завершите все сеансы в соответствующих приложениях, смените пароль на основном сайте либо в локальном аккаунте форума (в зависимости от способа входа), и сообщите администрации.

## Тесты

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Сценарии запускают сайт, форум и Wiki с **временными** базами данных и проверяют два отдельных входа, отзыв другого, отзыв всех и запрет операции без CSRF. В рабочие базы тесты не пишут.
