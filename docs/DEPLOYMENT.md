# Развёртывание OBSIDIAN RUSSIA

## 1. Что запускается

| Сервис | Каталог | Локальный порт | Точка проверки |
| --- | --- | ---: | --- |
| Сайт | `Сайт/` | 8080 | `/health` |
| Форум | `Форум/` | 8090 | `/health` |
| Wiki | `Вики/` | 8100 | `/api/stats` |

Для локальной разработки используйте Python 3.12+ и `python dev.py run`, либо `start-all.bat` в Windows.

Перед первым запуском выполните `python dev.py doctor`. Команда только проверяет наличие необходимых файлов и доступность локальных портов, не открывает сервер и не создаёт базы данных.

В продакшене запускайте **три независимых процесса** под отдельными ограниченными пользователями с собственными директориями данных. Не открывайте встроенные Python HTTP-серверы напрямую в интернет.

## 2. HTTPS и прокси

Размещайте каждый сервис за TLS reverse proxy с отдельным доменом или поддоменом. Примеры прокси находятся в `Сайт/deploy/`, `Форум/deploy/` и `Вики/deploy/` — адаптируйте их под реальные адреса и окружение.

Настройки приложения:

| Компонент | Базовый URL | Флаг Secure Cookie |
| --- | --- | --- |
| Сайт | `OBSIDIAN_BASE_URL` | `OBSIDIAN_SECURE_COOKIES=1` |
| Форум | `OBFORUM_BASE_URL` | `OBFORUM_SECURE_COOKIE=1` |
| Wiki | `OBWIKI_BASE_URL` | `OBWIKI_SECURE_COOKIE=1` |

Слушайте `127.0.0.1` (или изолированную внутреннюю сеть) и настройте ограничение запросов на уровне прокси. HTTPS должен работать **до** публикации форм регистрации и администрирования.

## 3. Базы и резервные копии

Никогда не используйте SQLite-файлы из старых Git-коммитов как готовые пользовательские данные. Для новых установок создаются свежие локальные базы.

При общем локальном запуске они лежат в `.runtime/site`, `.runtime/forum` и `.runtime/wiki`. При независимом запуске приложения по умолчанию используют собственные папки `data/`, если не заданы переменные:

- `OBSIDIAN_DATA_DIR`
- `OBFORUM_DATA_DIR`
- `OBWIKI_DATA_DIR`

Для локального backup выполните `python dev.py backup site`, `python dev.py backup forum`, `python dev.py backup wiki`. Для самостоятельных процессов запускайте соответствующие `manage.py backup` из директории каждого сервиса (для сайта: `python manage.py backup`).

SQLite следует копировать через штатный backup API, а не копировать только файл `*.sqlite3` при активном WAL. **Для Wiki отдельно сохраняйте `Вики/static/uploads/`** — база не содержит байты загруженных изображений.

Проверяйте восстановление копий на тестовом окружении и держите резервные копии за пределами публичного GitHub.

## 4. Единый вход

SSO между сайтом и форумом документирован в [SSO.md](SSO.md). Секрет клиента храните во внешнем менеджере секретов. Убедитесь, что callback, базовые адреса и HTTPS совпадают. У Wiki по-прежнему отдельные учётные записи редакторов.

## 5. Почта для восстановления пароля

Сброс забытого пароля требует SMTP через SSL или STARTTLS и корректный внешний `OBSIDIAN_BASE_URL` с HTTPS. SMTP-пароли храните вне репозитория; без настройки восстановление отключено.

[Полная инструкция по почте и ограничениям](PASSWORD_RECOVERY.md).

## 6. Перед публичным запуском

Проверить правила и политику конфиденциальности, защиту от спама, логи и наблюдаемость, ограничение внешних запросов, резервное копирование, системные обновления, разрешения файлов и отдельный аудит безопасности. Платёжная система и реальный мониторинг игрового сервера пока **не готовы**. Статус внутренних тестов не является подтверждением производственной безопасности.
