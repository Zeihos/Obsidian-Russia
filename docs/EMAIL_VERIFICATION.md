# Подтверждение и смена email — OBSIDIAN RUSSIA

[← Главная](../README.md) · [Восстановление доступа](PASSWORD_RECOVERY.md) · [Развёртывание](DEPLOYMENT.md)

## Что реализовано

Сайт OBSIDIAN RUSSIA различает **подтверждённые** и **неподтверждённые** адреса электронной почты. После регистрации на настроенном сайте отправляется письмо с одноразовой ссылкой. Подтверждение адреса позволяет пользоваться восстановлением забытого пароля.

- Ссылки подтверждения действуют **24 часа** и работают один раз.
- В SQLite хранится только **SHA-256-хеш** токена, назначение, пользователь, адрес и срок действия.
- У существующих аккаунтов статус email **по умолчанию «не подтверждён»**. Старые аккаунты, пароли, роли и данные при миграции сохраняются.
- Пользователь без подтверждённого email может войти по прежнему паролю и запросить повторное письмо из личного кабинета.
- **Сброс забытого пароля доступен только для уже подтверждённого email.** Не проверенные при регистрации старые адреса нельзя считать доказательством владения аккаунтом.
- Запросы отправки ограничены по IP и пользователю. При сбое SMTP недоставленный токен отменяется.
- Подтверждение выполняется POST-запросом с CSRF-защитой, не простым переходом GET по ссылке.

## Подтверждение после регистрации

При настроенном SMTP пользователь регистрируется, получает письмо и нажимает ссылку вида `https://site.example.org/verify-email?token=...`. После перехода открывается форма подтверждения. По нажатию «Подтвердить email» адрес получает статус подтверждённого.

Если SMTP **не настроен**, письмо не отправляется, а статус email остаётся неподтверждённым. Кнопка повторной отправки появится после настройки почтового сервера.

## Безопасная смена email

В разделе **«Личный кабинет → Безопасность email»**:

1. Пользователь указывает новый адрес и подтверждает **текущий пароль сайта**.
2. На **новый** email отправляется ссылка подтверждения.
3. Пока ссылка не подтверждена, в аккаунте остаётся **старый** адрес.
4. Для применения смены нужна исходная авторизованная сессия аккаунта и подтверждение нового email.
5. После успешной смены удаляются все действовавшие сеансы сайта и неиспользованные SSO-коды, увеличивается `auth_version` — форум отклоняет прежние связанные SSO-сеансы при следующем запросе.

Ссылку смены нельзя использовать для другого аккаунта, повторно или после истечения 24 часов. Нельзя занять email, уже используемый другим аккаунтом. Самостоятельная смена email **не требует** доступа к прежнему адресу, но требует текущего пароля и сессии; это полезно при утрате доступа к старому ящику. На прежний подтверждённый адрес теперь отправляются **best-effort уведомления** при запросе и завершении смены email, если SMTP работает. В [истории безопасности](ACCOUNT_SECURITY.md) сохраняются даты событий. Период ожидания и гарантированная доставка предупреждений пока не реализованы — перед публичным запуском рекомендована отдельная проверка рисков.

## SMTP

Используются **те же переменные окружения**, что и для [восстановления пароля](PASSWORD_RECOVERY.md): `OBSIDIAN_BASE_URL`, `OBSIDIAN_SMTP_HOST`, `OBSIDIAN_SMTP_PORT`, `OBSIDIAN_SMTP_FROM`, `OBSIDIAN_SMTP_SECURITY`, `OBSIDIAN_SMTP_USER`, `OBSIDIAN_SMTP_PASSWORD`.

Публичный адрес должен иметь HTTPS. Поддерживаются SMTP SSL и STARTTLS, без передачи писем через незащищённое соединение. Не сохраняйте секреты в GitHub.

## Ограничения

- Сами почтовые ящики и настоящая доставка писем **не проверяются в CI**. В тестах используются локальные временные SQLite-базы и имитация доставки.
- Система не отправляет письма без настроенного SMTP; реальное подключение провайдера — задача владельца сервера.
- Существующие неподтверждённые адреса не повышаются автоматически в подтверждённые: владелец сначала входит с паролем и запрашивает проверку.
- До публичного релиза нужны антибот-защита, постоянные лимиты на уровне прокси, контроль жалоб и проверка безопасности.
- Описанный функционал относится к аккаунтам **основного сайта**, а не к самостоятельным учётным записям форума или редакторам Wiki.

## Тестирование

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Покрываются создание неподтверждённого аккаунта, блокировка восстановления пароля до подтверждения, подтверждение через email, повторное использование токена, проверка текущего пароля при смене адреса, конфликт адресов, отказ для другой сессии, отзыв старых входов и обработка ошибок отправки.
