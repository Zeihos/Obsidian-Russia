# Единый вход OBSIDIAN RUSSIA: сайт → форум

## Текущий статус

**Опциональный SSO для сайта и форума**, без передачи пароля форуму.

Сайт выступает единственным провайдером учётной записи. Форум принимает
только короткоживущий **одноразовый код** и обменивает его на информацию об
аккаунте напрямую с сайтом, используя секрет клиента.

**Wiki пока не подключена к SSO.** Она содержит привилегированные аккаунты
редакторов, поэтому массовая регистрация посетителей не должна предоставлять
доступ к редактированию статей.

## Попробовать локально

Нужен Python 3.12+:

```bash
python dev.py run
```

Затем откройте http://127.0.0.1:8090/login и нажмите «Войти через аккаунт
OBSIDIAN RUSSIA». Если вы ещё не зарегистрированы на сайте, создайте аккаунт
на сайте, после чего продолжите вход на форум.

Лаунчер на каждом запуске создаёт временный секрет для локального обмена
между сайтом и форумом и подставляет нужные адреса. Секрет не сохраняется
в исходном коде. Коды авторизации действуют 90 секунд.

## Развёртывание на HTTPS

Настройте одинаковый случайный секрет **не менее 32 символов**
в переменных **разных процессов**:

| Сервис | Переменная | Пример значения |
| --- | --- | --- |
| Сайт | `OBSIDIAN_SSO_FORUM_SECRET` | длинное случайное значение |
| Сайт | `OBSIDIAN_SSO_FORUM_CALLBACK` | `https://forum.example.com/sso/callback` |
| Форум | `OBFORUM_SSO_CLIENT_SECRET` | то же значение |
| Форум | `OBFORUM_SSO_ISSUER` | `https://example.com` |

Также настройте штатные значения `OBSIDIAN_BASE_URL`,
`OBFORUM_BASE_URL`, HTTPS reverse proxy и `*_SECURE_COOKIE=1`
для всех сервисов. Внешний URL для обмена должен быть доступен **с сервера форума**.
В конфигурации разрешён HTTP только для loopback `localhost/127.0.0.1/::1`.

Защищайте секреты в переменных окружения / менеджере секретов.
Не храните их в GitHub и не помещайте в публичные примеры.
Для ручного запуска без этих переменных SSO отключён; старые
локальные формы регистрации и входа форума работают как раньше.

## Модель безопасности

1. Форум создаёт криптографически случайный `state`, который привязан
   к его анонимной серверной сессии и истекает через пять минут.
2. Пользователь переходит на сайт и авторизуется в веб-аккаунте.
3. Сайт выдаёт одноразовый код (90 секунд), сохраняет только SHA-256 хеш
   и перенаправляет браузер **только на заранее заданный callback** форума.
4. Форум проверяет `state` и его сессию, удаляет `state`, затем
   обменивает код через сервер-сервер POST с секретом.
5. Сайт атомарно погашает код; повторная попытка отклоняется.
   Форум создаёт собственную авторизованную сессию.

Коды не содержат пароль или права администратора. Все новые пользователи
форумного SSO создаются с ролью **member**. Даже если пользователь администратор
на сайте, он не получает прав модератора или администратора форума автоматически.

Уже существующие аккаунты форума **не объединяются автоматически** по имени
или email. Сайт пока не подтверждает владение email, и автоматическая
стыковка могла бы позволить захват аккаунта. Для первого SSO-входа
создаётся новый форумный профиль, а связывание с существующим профилем
потребует отдельной процедуры подтверждения владения обеими учётными записями.

Пароль нового SSO-профиля локально случайный и пользователю не показывается.
Смена пароля доступна на основном сайте, не на форуме.

## Что не входит в эту версию

- Единый logout и принудительный отзыв **всех** сессий при смене пароля на сайте.
- Перенос старых форумных аккаунтов или объединение профилей.
- Wiki SSO для специально уполномоченных редакторов.
- Подтверждение email, второй фактор, recovery flow, единая админ-панель.
- Подключение игрового аккаунта/персонажа.

Перед публичным запуском дополнительно нужны независимый аудит,
защита от массовых регистраций и спама, резервное копирование,
мониторинг и проверка reverse proxy.

## Автоматические тесты

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

`tests/test_sso.py` поднимает реальные локальные HTTP-серверы с временными
базами, создаёт пользователя, проходит полный цикл входа на форум
и проверяет отказ при повторном коде или неверном секрете.
